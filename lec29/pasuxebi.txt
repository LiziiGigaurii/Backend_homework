1.1. რა მონაცემთა ტიპები ვიცით JavaScript-ში? (Primitive vs Non-Primitive)
primitive არის ისეთი მარტივი სტრუქტურები, რომლებსაც ვერანაირად ვერ შევცვლით (string, undefined, number , boolean, null)
nonprimitive პირიქით რთული სტრუქტურაა, რომლის შეცვლის უფლებაც გვაქვს (Object, function, array)


1.2. რა განსხვავებაა ცვლადის გამოცხადების ტიპებს შორის: var, let და const?
var ძველი ტიპია, მთელ ფუნქციაში მუშაობს. 
let შეგვიძლია შევცვალოთ, ხოლოდ იმ ბლოკში მუშაობს სადაც არის დაწერილი. 
const კი ერთხელ ანიჭებ მნიშვნელობას და მეტს ვერ შეცვლი


1.3. განმარტეთ Call Stack და Memory Heap: რა განსხვავებაა მათ შორის და სად ინახება მონაცემები?
Call Stack არის ადგილი, სადაც ჯავასკრიპტი ინახავს ფუნქციების გამოძახებებს და თვლის ამჟამად რომელ ფუნქციაშია.
Memory Heap კი სხვა ადგილია, სადაც ინახება ობიექტები და მასივები. უფრო დიდი და არასტრუქტურირებული სივრცეა


1.4. რა არის Event Loop (მოვლენათა ციკლი) Node.js-ში და როგორ მუშაობს ის?
ის ელოდება Call Stack-ის გათავისუფლებას, და შემდეგ Callback Queue-დან ასინქრონულ ამოცანებს უშვებს შიგნით. 
ეს აძლევს ჯავასკრიპტს ასინქრონულობის საშუალებას, მიუხედავად იმისა, რომ ის single-threaded ენაა


1.5. რა არის Promise? აღწერეთ მისი მდგომარეობები (States) და რით განსხვავდება ის Callback-ებისგან?
Promise არის ისეთი პირობა, რომელიც საბოლოოდ აუცილებლად დააბრუნებს ან fulfilled-ს ან rejected-ს. 
სამი მდგომარეობა აქვს - pending, fulfilled და rejected. Callback-ისგან განსხვავდება იმით, 
რომ არ ჩნდება callback hell და უფრო წაკითხვადია


1.6. რა არის Async/Await და როგორ მუშაობს ის Promise-ების ბაზაზე?
ძირითადად fetch-ის (API-ის) დროს ვიყენებთ. ამ დროს კოდი სინქრონულად გამოიყურება, 
თუმცა სინამდვილეში ასინქრონულად მუშაობს — Promise-ს ბაზაზეა აგებული


1.7. რა არის Class (კლასი) JavaScript-ში და რა არის OOP-ის (ობიექტზე ორიენტირებული პროგრამირების) ძირითადი პრინციპები?
Class არის ერთგვარი ბლუპრინტი, ნიმუში, რომელსაც აღვწერთ სხვადასხვა მეთოდებითა და თვისებებით. მისი დახმარებით ვქმნით ობიქეტს. 
ობიექტი უკვე class-დან new-ით შექმნილი კონკრეტული მაგალითია. OOP-ის პრინციპებია: Encapsulation (მონაცემის დამალვა), 
Inheritance (მემკვიდრეობა), Polymorphism (ერთი მეთოდის სხვადასხვაგვარად მუშაობა) და Abstraction (მხოლოდ საჭირო ნაწილის ჩვენება)

2.1. რა არის Request-Response?
კლიენტი სერვერს უგზავნის მოთხოვნას (Request), სერვერი ამუშავებს და პასუხს (Response) უკან უბრუნებს.
ეს არის მთელი web კომუნიკაციის საფუძველი


2.2.ჩამოთვალე რექვესთები და მათი თავისებურება განმარტე.
GET — მონაცემის მისაღებად, body არ აქვს
POST — ახალი მონაცემის შესაქმნელად, body-იგით
PUT — მონაცემის მთლიანად ჩანაცვლებისთვის
PATCH — მონაცემის ნაწილობრივი შეცვლისთვის 
DELETE — მონაცემის წასაშლელად


2.3. რა განსხვავებაა URL Params-ს, Query Params-სა და Request Body-ს შორის? (როდის რომელს ვიყენებთ?)
URL Params გამოვიყენებთ, როცა კონკრეტული რესურსის იდენტიფიცირება გვინდა, მაგალითად /users/:id
Query Params კი ? ნიშნის შემდეგ იწერება და ფილტრაცია ან სორტირებისთვის გამოგვადგება, მაგალითად /users?page=1
Request Body გამოვიყენებთ, როცა დიდი ან კომპლექსური მონაცემი გვაქვს გასაგზავნი, ჩვეულებრივ POST/PUT-ში


2.4. რა არის Middleware Express.js-ში/NestJS-ში და რაში გამოიყენება ის?
ეს არის ფუნქცია, რომელიც Request-სა და Response-ს შორის ჩარევს, request-ს, response-ს და next()-ს იღებს. 
გამოვიყენებთ authentication-ისთვის, ლოგირებისთვის, ვალიდაციისთვის


3.1. რა არის შრეობრივი არქიტექტურა (Layered Architecture) და რა პასუხისმგებლობები აქვთ:
     - Controller 
     - Service 
     - module
Controller-ი იღებს HTTP მოთხოვნას და აბრუნებს პასუხს
Service შეიცავს ლოგიკას და მთავარ სამუშაოს მონაცემებთან 
Module აჯგუფებს ერთმანეთთან დაკავშირებულ controller-ებსა და service-ებს ერთ ლოგიკურ ბლოკად


3.3. რა არის Dependency Injection (DI) ?
ეს არის მიდგომა, როცა კლასი თავად არ ქმნის თავის დამოკიდებულებებს, არამედ ისინი გარედან, 
ჩვეულებრივ constructor-ის საშუალებით ეძლევა. ამის წყალობით კოდი უფრო ადვილად ტესტირებადი ხდება


3.4. რა არის DTO (Data Transfer Object) და რატომ ვიყენებთ მას Validation Pipe-ებთან ერთად?
DTO არის კლასი, რომელიც აღწერს ზუსტად როგორი "ფორმის" მონაცემი უნდა მოვიდეს ან წავიდეს. 
მას class-validator-ის დეკორატორები ერთვის (მაგალითად @IsString(), @IsEmail()) 
ესენი ValidationPipe-ს საშუალებას აძლევენ ავტომატურად შეამოწმონ შემომავალი მონაცემი, სანამ ის Controller-მდე მიაღწევს
